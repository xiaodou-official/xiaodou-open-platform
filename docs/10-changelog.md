## 1. 版本策略（先读这一段）

| 规则 | 说明 |
| --- | --- |
| 路径内带版本 | 接口路径里的 `v1` 是**主版本**；主版本内**只增不改** |
| 字段只增 | 主版本内**不删除、不改名、不改语义**；新字段一律可选 |
| 不兼容变更 | 必须升 `v2` 并**与 `v1` 平行运行至少一个公告周期**（先公告、后下线） |
| 公告先行 | 任何影响商家代码的变更，先发公告，再改行为 |
| 同源发布 | 每次发版在三处同源发布：**门户公告栏**（平台内的商家公告位）、**本文档「更新日志」**、**公开发布页**；公告正文只有一份（见 `releases/`） |

**你要做的**：对 `code` 与字段做**宽松解析**（多字段不报错），对新增枚举值做兼容分支；这样主版本内的变更不会打断你。

## 3. 更新日志

### v1.0.0

**新增**

- **支付宝官方收款码面向商家下发**：下单响应新增 `qrCode` 字段（仅支付宝渠道、服务端校验官方前缀后下发），商家可在**自有 PC 页面**直接渲染官方收款码，与平台收银页同形。
  - 下发语义：**只有下发响应有效**；查询接口恒为 `null`；需要新码走**重拉起**端点（新尝试=新码）。
  - 覆盖三个端点：创建订单（下发）、重拉起（换新码）、查询（恒空）。
- **收银页终端分端能力**：同一收银 URL 按终端分派——PC 渲染二维码；手机浏览器（微信外）支付宝单给**手势主按钮「打开支付宝」**（渲染顺序=二维码 → 主按钮 → 按钮下的兜底说明，三样都在买家手势之前已渲染；**无手势的自动跳转已被真机证伪，不再采用**）；手机微信内支付宝单不自动跳转（只给复制链接引导）。
- **微信支付「免手点」**：手机微信内进入收银页即自动完成授权并调起支付面板，买家无需先点一次按钮。
- **手机微信外推荐路径**：微信支付单在手机微信外给出**可执行**的一键引导（复制链接并打开微信 + 三步说明 + 如实兜底），逐字文案见 [收银页对接 · 第 4 节](./06-cashier-integration.md#4-手机微信外推荐路径逐字引导文案)。

**明确不支持（不要按这些形态设计）**

- 微信**没有**「正扫」形态：微信的 PC 扫码本质是**中转链**（二维码 → 手机微信内 → 页面调起）。
- 手机浏览器（微信外）**没有**「直接拉起微信支付」形态。
- 商家的自有 App **不得**用 WebView 内嵌打开收银页（必须跳系统浏览器）。

**迁移动作**：无需迁移。本次为**只增不改**：新字段 `qrCode` 为可选，旧解析逻辑不受影响；收银页行为变化只作用于买家侧体验，商家的服务端对接无需改动。

## 4. 已取消/不支持的形态（历史公告残留，防误用）

平台**不提供**下列形态，任何历史资料、截图或口口相传里的这些说法都不成立：

- 微信「原生扫码」直出付款码（见上：不存在）。
- 手机浏览器直接拉起微信支付面板。
- 平台侧托管收款页（收款页形态只有本资料描述的两类：自渲染官方收款码 / 平台收银页）。
- 在本资料里出现过的任何「时效承诺」或「固定费率」——均已作废，一律以**生效配置**与**每单投影**为准。
