# 费率与限额

> docId：`XD-OP-07` ｜ version：`1.0.0` ｜ status：`PUBLISHED`

> **本篇不写死任何费率、限额与时效数字。** 生效值随平台配置变更，取「**生效配置**」或「**每单投影**」才是正确做法；把它们抄进代码或文案是上线事故的常见起点。

## 1. 三个口径，只认两个

| 口径 | 从哪来 | 用途 |
| --- | --- | --- |
| **生效配置** | 门户「费率」展示的**全局公开档位**（带版本标识） | 了解平台公开口径；**不含**平台为你单独调过的档位（单商家调整不进该投影） |
| **每单投影**（`feeProjection`） | 每一笔订单响应里返回 | **入账与对账的唯一依据** |
| ~~文档里的数字~~ | —— | ❌ 不存在：本资料不写死数字 |

**入账必须用 `feeProjection`**：同一笔订单在创建时冻结口径，后续平台配置变更**不会**改变已创建订单的费率——所以历史订单永远能对得上。

## 2. `feeProjection` 字段

| 字段 | 说明 |
| --- | --- |
| `ruleVersion` | 该笔适用的配置版本标识（对账时用它比对） |
| `thresholdFen` | 配置中的中性分档字段（可能不适用于你的档位；**不要**用它自己算费率） |
| `tier` | 该笔命中的档位标识。当前平台为**统一费率**，取值恒为 `STANDARD`——**它不参与金额计算**，别用它做分支判费率 |
| `merchantRateBps` | 你的**结算比例**（万分比） |
| `companyServiceFeeRateBps` | **公司服务费比例**（万分比） |
| `merchantSettlementFen` | 该笔结算金额（整数分） |
| `companyServiceFeeFen` | 该笔公司服务费（整数分） |

约定：

- **对外只出「你的结算比例 + 公司服务费」这两个口径**。服务费内部如何分配是平台内部事项，不对商家展示、也不影响你的入账金额。
- `merchantSettlementFen + companyServiceFeeFen` 与实付金额闭环（差额分配规则由服务端处理，商家不需要自己算）。
- **不要**在代码里维护一份「费率表」并对账，那一定会在某次配置变更后错账。

## 3. 限额

限额有三个层级，越靠前的越优先：

1. **单商家调整**（平台为你单独设置过生效窗）；
2. **应用/商家档位**（准入档位对应的限额）；
3. **平台全局档**。

> **限额值不在本资料、也不在门户展示**（门户只展示全局公开费率档位；单商家限额与调整申请暂无自助面）：被 `422 OPEN_API_LIMIT_EXCEEDED` 拒时，按下面三条自查，需要调整就通过官网反馈渠道提（附 `requestId`），以平台答复的生效值为准。**不要**用试探下单的方式去摸限额边界。

- 越界返回 `422 OPEN_API_LIMIT_EXCEEDED`。
- **限额是「拒绝」不是「排队」**：被拒的订单不会稍后自动成功，请在业务侧给买家明确提示。
- 「在途未支付金额」也计入限额：**先关掉不再支付的订单**，再创建新单。

## 4. 结算与到账

- 支付成功后资金按平台与支付机构的结算规则结算到你的结算账户。
- **自动结算周期、到账时间、是否支持手动提现**都属于会变更的口径：**以门户「资金/结算」视图展示的生效配置为准**，不要写进你的对外文案里。
- 你可以在门户「资金/结算」视图看到按渠道的结算状态与逐笔订单的结算情况；订单维度看 `feeProjection`。

## 5. 常见误区

1. **把文档/门户截图里的数字写进代码** → 配置变更后错账。
2. **用 `thresholdFen` 自己推算费率** → 该字段是中性字段，不代表你的实际档位。
3. **按「本金 × 比例」自己算服务费** → 分配与取整由服务端计算，自己算会差分。
4. **在对外文案承诺具体到账时效** → 到账周期会随渠道与结算规则变化。
