# 终端能力矩阵与收款页形态

> 人读版：`docs/06-cashier-integration.md`（含逐字文案）（**不在本 Skill 包内**：Skill 包只含 `skill/**` 与 `examples/**`，需要时从门户「文档下载」包或公开仓的 `docs/` 取）。

## 1. 矩阵（四端 × 两通道）

| 终端 | 支付宝 | 微信 |
| --- | --- | --- |
| PC 浏览器 | 渲染官方收款码，页内扫码，**不跳转** | 渲染**平台收银页地址**的二维码（扫码后进手机微信内，再由页面调起） |
| 手机 · 微信外 | 官方收款码 + **手势主按钮「打开支付宝」**（点击内打开官方收款码）；兜底=长按识别 / 截屏 → 支付宝扫一扫 → 相册 | **推荐路径**：复制链接并打开微信 + 三步说明 |
| 手机 · 微信内 | **不自动跳转**，给「复制链接到系统浏览器打开」引导 | **零点击**自动授权并调起支付面板 |
| 商家 App / 宿主内 | 先**跳系统浏览器**，落地后按「手机 · 微信外」给手势按钮 | 先**跳系统浏览器**，落地后按「手机 · 微信外」走**推荐路径**（App 内没有「直接调起微信支付」形态，见 §4） |

**为什么**：平台**没有**「微信正扫」形态——微信支付只能在微信内由页面调起，所以微信的 PC 扫码本质是**中转链**。不要向买家承诺「扫码直接出付款码」，也不要实现「手机浏览器直接拉起微信支付」。

**桌面微信内置浏览器也命中「微信内」分支**（平台按 UA 判定，不为桌面微信单独分派形态）：链接在 PC 微信里被打开时，同样走微信内的授权/调起链；买家在 PC 微信里完不成支付，让他**用手机微信打开同一条链接**即可——不要为此在自有容器里另做一套。

**矩阵 = 能力面，不等于通道已放开**：通道**链路是否放行**由平台整体控制（**不区分应用**），粒度是「**通道 × 交易形态**」；未放行的组合下单返回 `422 OPEN_API_CHANNEL_UNAVAILABLE`（可预期的正常拒绝，不要重试刷量）。**平台没有自助查询面**——接入前与对接人确认你要用的组合是否已放行，不要靠试探下单确认，也不要按「两个通道都一定能下单」写死分支或对外文案。

## 2. 两种收款材料用法

### 用法一：自渲染官方收款码（`qrCode`）

```text
取响应 qrCode
 ├─ null → 该单不下发（渠道不符/非官方码/无有效尝试）：改用 payUrl 中转链
 └─ 非空 → 渲染前做前缀防呆复检（只接受官方收款码前缀）
            ├─ 通过 → 渲染二维码（商家自有 PC 页面）
            └─ 不通过 → 不渲染、不报错、不打印，回退 payUrl
```

- 仅支付宝渠道、仅官方前缀才会下发；**前端不得拼装/改写/代理转发**。
- 不得进日志、埋点、管理面、事件通知。
- **只在下发响应有效**：查询接口恒 `null`；需要新码走**重拉起**（新尝试=新码），旧码不可复用。

### 用法二：`payUrl` 中转链

| 方式 | 做法 | 终端语义 |
| --- | --- | --- |
| 渲染二维码 | 把 `payUrl` 渲染成二维码（商家 PC 页面） | 被扫方=PC，扫码方=手机 → 手机进收银页 → 按矩阵分端 |
| `302` 跳转 | 浏览器 `302` 到 `payUrl` | 买家浏览器直接进收银页 → 按矩阵分端 |

用 `payUrl` **原值**，不加自己的 query；终端分派由平台收银页负责，商家侧**不要**自己判断终端。

## 3. 手机微信外推荐路径（逐字文案）

| 键 | 逐字文本 |
| --- | --- |
| 标题 | `请在微信中打开完成支付` |
| 说明 | `微信支付需要在微信内打开本链接；点击下方按钮复制链接并打开微信；链接发给自己即可。` |
| 主按钮 | `复制链接并打开微信` |
| 步骤 | `打开微信` / `把链接粘贴发送给「文件传输助手」` / `点开链接即可进入支付` |
| 复制成功 | `已复制链接，正在打开微信…` |
| 复制失败 | `未能自动复制，请长按下方链接手动复制` |
| 手动框可访问名 | `支付链接` |
| 取不到链接 | `支付链接获取失败，请返回商家页面重新打开` |
| 如实出口 | `如需使用支付宝支付，请联系商家重新选择支付方式。` |

约束：复制先独立成功再尝试唤起；唤起失败不回滚复制；不用顶层 `location` 赋值跳 `weixin://`（用临时锚点点击，页面保留）；复制失败要给可手动复制的只读文本框。**不要承诺「点一下就到支付面板」**。

## 3b. 手机微信外 · 支付宝单（逐字文案）

| 键 | 逐字文本 |
| --- | --- |
| 打开支付宝主按钮 | `打开支付宝` |
| 按钮下就地说明 | `没打开？长按二维码识别；识别不了就截屏保存，打开支付宝 → 扫一扫 → 相册 → 选刚截的图` |

**不要**实现「进入即自动打开支付宝」（真机实测：无手势的自动跳转会被浏览器策略吃掉，两个主流手机浏览器均不跳），也**不要**做「复制支付链接 → 支付宝打开」（支付宝没有粘贴链接付款入口）。跳转只在买家点按钮的手势内发生。渲染顺序是**二维码 → 主按钮 → 按钮下的兜底说明**：三样都要在买家手势之前就进 DOM（跳不动、被策略吃掉或用户取消时页面仍然可用），但兜底说明的**位置在按钮下方**，不要挪到按钮上面。

## 4. 宿主内硬约束

- ✅ 自有 App 用**系统浏览器**打开收银链。
- ❌ 禁止 WebView / 内嵌浏览器打开收银页（UA 与浏览器特性失真 → 终端判定错 → 买家落到拉不起来的页面）。
- ❌ App 内没有「直接调起微信支付」形态；App 内的微信支付同样走推荐路径。
