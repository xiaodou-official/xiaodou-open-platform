# 凭证与密钥管理

> 人读版：`docs/12-credential-key-management.md`（**不在本 Skill 包内**：Skill 包只含 `skill/**` 与 `examples/**`，需要时从门户「文档下载」包或公开仓的 `docs/` 取）。

## 1. 生成

1. 门户「应用凭证」页发起；**密钥对在你的浏览器本地生成**，私钥不经过平台。
2. 上传公钥时平台要求一次**持有证明**：用**新私钥**对确定性挑战串（绑定应用标识与公钥指纹）签名。
3. 提交需通过**操作二次验证**（绑定手机的操作码）——防止会话被盗后悄悄换钥匙。
4. 平台回显**公钥指纹**与 `kid`；把 `kid` 记进配置。

### 1.1 `kid` 的格式、来源与本地派生

- **格式**：`mkid_` + 16 位小写十六进制（共 21 字符），例如 `mkid_5f3c1a7b52e84d06`。
- **来源**：**不是平台预先发放的**——在你上传公钥成功的那一刻，平台按公钥指纹派生并回显（门户「应用凭证」页）。**没有上传过公钥的应用，任何地方都不存在它的 `kid`**。
- **本地派生（可自动计算，无需向平台索取）**：导出公钥 SPKI PEM（`-----BEGIN PUBLIC KEY-----` 头，RSA 2048/4096）→ 规范化（CRLF→LF、去首尾空白、末尾不留换行）→ `kid = "mkid_" + SHA-256(规范化文本的 UTF-8 字节) 的前 16 位小写十六进制`。上传与本地计算用**同一份文本**（导出 → 规范化 → 上传同一路径），两边必然一致。
- **两个 `kid` 别混**：门户「应用凭证」页同时展示——「**商户公钥 kid**」是你自己的，签名请求头 `X-XD-Key-Id` 填它；「**平台公钥 kid**」是平台的（核验平台响应/事件签名用），**不要**填进请求头或对接配置的「密钥标识」项。

## 2. 轮换（关键：切换是原子的）

- 提交成功后：**新 `kid` 立即生效**，必须**立刻**改用新私钥签名。
- **默认态下旧密钥在同一瞬间失效**：平台只接受当前生效的 `kid` 与公钥（历史条目默认只用于审计追溯，不能继续签名）。
- 因此存在一个「平台已切 → 你还没切」的短窗口，期间用旧私钥签名的请求会 `401`。
- **可选过渡宽限窗**：短窗口不可接受时，**轮换前**联系平台运营申请开启「旧密钥验签宽限窗」——窗口内已下线的旧 `kid` 仍可验签、到期自动失效、平台可立即关闭、上限 72 小时；**只允许验签**（不恢复管理/配置权限）；**密钥疑似泄露时不适用**（先轮换止血）。

推荐顺序：

```text
① 低峰期，准备好一键切换（新私钥 + 新 kid）；若已约定宽限窗，先与对接人确认已开启并**记下到期时间**（门户不显示窗口状态）
② 门户完成轮换（生成 → 持有证明 → 二次验证 → 提交）
③ 提交成功后立刻切换服务端配置并发布
④ 窗口内对 401 做有限次重试；观察成功率与签名告警恢复
⑤ 确认无异常后销毁本地旧私钥
⑥ 记录本次轮换时间/kid/执行人/结果
```

> 先在预发演练同一流程与同一配置项，再动生产。

## 3. 停用与吊销

| 动作 | 效果 |
| --- | --- |
| 暂停应用 | **商家 API 全部不可用**（应用非 ACTIVE 时鉴权阶段即失败，实际拿到 `401`，不是 `403`）——存量查询/关单/退款也一并打不通，只能转平台人工通道 |
| 吊销应用 | **永久终态**：商家 API 全部不可用，退款仅保留平台人工通道 |
| 冻结（风控） | 新增下单/支付尝试被拒；存量不受影响 |
| 移除 IP 白名单 | 对应出口立即 `403` |
| 关闭来源 IP 校验（门户自助） | 所有来源不再被校验；条目原样保留，可一键重开。平台边缘判定不受影响 |

## 4. 私钥丢失/泄露（按顺序）

1. **立刻轮换**（不需要停机、不需要等人工）。
2. 查自己的调用日志与平台 401/403 告警，看是否有异常调用。
3. 怀疑 `appId` 被滥用 → 走官网反馈渠道申请**停用应用**。
4. 销毁本地旧私钥与任何携带它的临时文件/镜像层/构建缓存。

## 5. 纪律

- **一应用一套密钥**，不跨应用/跨环境复制。
- 密钥进运行时注入或密钥服务，**不进仓库**；本地开发也不用生产密钥。
- 不要把私钥下发给客户端（前端/移动端）——签名只在服务端做。
