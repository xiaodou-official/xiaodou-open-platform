# 本地收银 demo（H5）

零外部依赖、零生产连接：一个 Node 进程里同时扮演**模拟平台**、**商家后端**与**静态页面**，把「下单 → 收银页 → 终端分派 → 状态轮询 → 事件验签落账 → 查单补偿 → 退款」整条链跑通。

```bash
node demo/h5-cashier/server.js          # 默认 http://127.0.0.1:8787/
node demo/h5-cashier/server.js --port 9000
```

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 商家控制台 | `/` | 建单、重拉起、查单、关单、退款、模拟买家完成支付；看事件与调用日志 |
| 终端预览 | `/preview.html` | 手动切换 PC / 手机微信外 / 手机微信内，看买家的实际形态 |
| 收银页（mock） | `/cashier/{token}` | 收银页示意，按终端与通道渲染不同分支 |

## 1. 这个 demo 里什么是真的

- **请求签名是真的**：商家后端调模拟平台时真的生成 `XD-Signature-v1` 六头；模拟平台真的验签，签名不对一律 `401`。
- **事件验签是真的**：模拟平台按 `XD-Webhook-v1` 对事件体原始字节签名并投递；商家后端用平台公钥验签、按 `eventId` 去重，成功才回 `success`。
- **状态链路是真的**：查单是本地权威读（材料恒空）、重拉起换新收款材料、未支付订单不可退款。
- **终端分派是真的**（按 `docs/06` 的矩阵）：PC 渲染二维码不跳转；手机微信外支付宝单给**手势主按钮**，按钮**下**就地给兜底（二维码 → 按钮 → 兜底说明三样都先于买家手势进 DOM）；手机微信内微信单零点击。

## 2. 什么是假的（别照抄进生产）

- **二维码是示意图**：页面上画的是确定性图案，**不可扫描**，只用于演示形态位置。
- **支付机构是内存模拟**：没有真实资金动作，没有外部网络调用。
- **密钥是进程内生成的临时密钥**：不落盘、不进仓库；生产请用你自己的密钥管理方式（见 `docs/12`）。
- **收银页是示意页**：真实收银页由平台承载，请不要照抄它的样式去仿造平台收银页。

## 3. 冒烟自检

```bash
node demo/h5-cashier/smoke.js
```

会把 demo 当真实进程拉起来跑完整条链（含未签名/签名篡改/未知单号的负向用例），最后打印 `[OK]` 或失败清单。**这是本地唯一的「跑通」证据**——它不证明生产链通（mock 不替代生产首单）。

## 4. 通道说明

- **支付宝优先**：PC 与手机都支持；手机浏览器（微信外）给手势主按钮「打开支付宝」，渲染顺序是**二维码 → 主按钮 → 按钮下的兜底说明**（长按识别 / 截屏 → 支付宝扫一扫 → 相册）——三样都在买家手势**之前**就已渲染。**无手势的自动跳转已被真机证伪，本 demo 同样不实现。**
- **微信**：只能在**微信内**完成支付——PC 渲染的是平台收银页地址的二维码（扫码后进微信内，由页面调起支付面板）；手机微信外走**推荐路径**（复制链接并打开微信 + 三步说明）。**平台没有「在微信外直接拉起微信支付」的形态**，请不要按那种预期设计交互。
- **通道未放行时的拒绝是正常语义**：`422` 表示该通道当前不可用，按可预期拒绝处理，不要重试刷量。

> 本 demo **不包含**任何已取消或不存在的支付形态（例如「微信原生扫码直出付款码」「平台侧托管收款页」「手机浏览器直接拉起微信支付面板」）。历史资料里出现过的这类说法一律不成立，见 `docs/10-changelog.md` 第 4 节。
