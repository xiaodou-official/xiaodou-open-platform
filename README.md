## 这是什么

一句话：**你负责卖，平台负责把钱收进来、把状态讲清楚、按结算配置把钱结给你。**

平台提供的能力边界是**支付事实**，不是电商系统：

| 平台负责 | 商家负责 |
| --- | --- |
| 下单受理、收款、支付状态与终态事件 | 商品、库存、定价与页面 |
| 查单、关单、退款与退款查询 | **交付本身**：卡密发放、服务开通、发货、开票、售后 |
| 每单费率投影（`feeProjection`）与结算 | 你的订单库、对账与售后 |
| 域名归属验证、IP 白名单、请求/响应/事件三套签名 | 你的密钥保管与轮换 |

**交付由你自己的系统完成**：收银页不承载交付内容，`returnUrl` 也**不是**终态通知——终态只认查单与经验签的事件（详见 [接入指南](./docs/02-integration-guide.md)）。

## 能力一览

**六个商家 API**（路径相对平台下发的 `<BASE_URL>`，主版本 `v1`，主版本内只增不改）：

| 端点 | 作用 |
| --- | --- |
| `POST /api/open/v1/payments` | 创建支付订单（业务幂等） |
| `POST /api/open/v1/payments/{outTradeNo}/attempts` | 重拉起支付尝试（换新收款材料） |
| `GET /api/open/v1/payments/{outTradeNo}` | 查询订单（本地权威读） |
| `POST /api/open/v1/payments/{outTradeNo}/close` | 关闭订单（先与支付机构确认未支付） |
| `POST /api/open/v1/refunds` | 创建退款（业务幂等） |
| `GET /api/open/v1/refunds/{outRefundNo}` | 查询退款 |

**收款材料两种标准用法**：自有 PC 页面**自渲染官方收款码**（`qrCode`，仅支付宝渠道下发）、或把平台收银页地址（`payUrl`）渲染成二维码 / `302` 跳转。细节见 [收银页对接](./docs/06-cashier-integration.md)。

**三套独立签名**：请求 `XD-Signature-v1`（你签）、响应 `XD-Response-v1`（平台签）、事件 `XD-Webhook-v1`（平台签）。三套规范串**不一样**，不要复用同一段拼串代码；平台公钥与指纹在 [接入指南 §3.1](./docs/02-integration-guide.md#31-平台公钥与指纹公示) 公示。

**硬纪律（先记这四条，能避免绝大多数事故）**：

1. **收银页打开 / 回跳 / 用户点完成，都不是支付终态** —— 终态只认查单或经验签的事件。
2. **重试复用同一个 `requestId` 与同一份请求体**；`409` 的正确动作是**查单**，不是换单号重下单。
3. **`UNKNOWN` 不判死**：不重新下单、不重发退款、不提示买家失败，等事件或查单收敛。
4. **私钥永不进浏览器、不进仓库、不进日志**；费率与限额**不写死**，以每单 `feeProjection` 与门户生效配置为准。

## 资金与结算

- **资金不经过平台账户沉淀**：支付成功即按**下单时冻结的收款分配**实时分账到各方，平台提供的是接入、状态与对账能力，**不是支付机构**。
- **清算与结算由持牌第三方支付机构完成**，出金按结算配置**自动结算到已绑定的结算卡** —— **不需要手动提现**。现役结算周期为**次自然日（D1，含节假日）**。
- **费率不在本资料里写死**：每笔订单响应里的 `feeProjection`（含 `ruleVersion`）就是该笔的生效口径；门户可看当前生效配置。
- 结算周期、到账时效与通道放行状态**都会变**：一律**以门户「资金/结算」与「应用」视图展示的生效配置为准**，不要写进你的对外文案或代码常量。

## 常见问题（FAQ）

**这是「虚拟发卡平台」吗？**
本开放平台只做**收款与支付事实**，交付（卡密发放 / 开通 / 发货）由你自己的系统完成。如果你要的是「上架卡密就能卖」的一站式发卡，用**小豆集市**的卖家门户，不必写代码。两者资金链一致。

**支持微信收款和支付宝收款吗？**
两条通道的**终端能力**都已实现（支付宝：官方收款码 + 收银页；微信：微信内由页面调起支付面板）。**支付宝通道当前已开闸**，可直接接入；**微信通道的链路放行按你应用的生效配置**，尚未放行时下单返回 `422` `OPEN_API_CHANNEL_UNAVAILABLE`——这是**可预期的正常拒绝**，不要按故障处理或重试刷量。接入前先在门户确认你的应用放行了哪些通道。

**钱多久到账？要手动提现吗？**
支付成功即实时分账离账，随后按结算配置**自动结算到已绑定的结算卡**——**不需要手动提现**。现役结算周期为**次自然日（D1，含节假日）**；周期与时效会随渠道和配置变化，以门户「资金/结算」视图为准。

**平台会经手或沉淀我的资金吗？**
不会。平台**不是支付机构、不接触交易资金**：清算与结算由**持牌第三方支付机构**完成，支付成功即按冻结的收款分配实时分账到各方。

**你们是「易支付 / 码支付」那类系统吗？**
不是，两者资金路径完全不同。那类叫法通常指**免签 / 第四方代收**：用个人收款码或代收账户先把钱收进来、再转付给卖家，**资金会经过中间方账户**。我们走的是另一条路：**商家在持牌第三方支付机构开立自己的结算账户**，买家付款后资金在机构侧**实时分账**到各方账户，再按结算配置自动结算到绑定的结算卡 —— **平台不接触交易资金，也不做代收转付**。如果你要的是前者，我们不适配；如果你要的是「有正规结算账户 + 一个 API 接完微信和支付宝 + 次自然日自动到账」，继续往下看即可。

**手续费多少？**
本资料**不写死任何费率**。每笔订单响应里的 `feeProjection` 就是该笔的生效口径（含 `ruleVersion`，用它对账）；门户可看当前生效配置与限额档位。详见 [费率与限额](./docs/07-fees-and-limits.md)。

**有沙箱或测试环境吗？**
暂不提供沙箱、测试应用与回调模拟器。替代路径：本地 demo（零外部依赖，全链 mock）+ [上线检查清单](./docs/11-go-live-checklist.md) + 首次生产小额首单的人工陪跑（**不承诺 SLA**）。**mock 全绿只证明签名与解析没错，不证明资金链通。**

**要自己写代码吗？接哪些语言？**
接入是**服务端到服务端**的：下单/查单/退款 + 事件验签。仓库提供 Node.js / Java / PHP / Python 四份**产出完全相同规范串**的签名示例，含 golden 向量；事件验签另有 Node 参考实现。

**收银页能自己设计吗？**
两种标准形态：在**你自己的页面**渲染官方收款码，或把 `payUrl` 渲染成二维码 / `302` 跳转。**不要仿造平台收银页的样式**——真实收银页由平台承载且**品牌中立**，也不要在自有 App 的 WebView 里内嵌打开（必须跳系统浏览器）。

**怎么开通？**
从线上入口（见页首）进「卖家中心 / 免费开店」→ 注册小豆账号并完成**商户进件** → 签署开放平台服务协议与经营范围合规报送同意书 → **一键申请应用**（受理即自动审核）→ 取得 `appId`、`kid` 并登记你的 RSA2 公钥、配置出口 IP 白名单与 `notifyUrl`。申报的每个网站域名都要先完成**域名归属验证**（DNS TXT 或回源文件二选一）。

**密钥怎么轮换？**
平台用同一把 RSA2 密钥对响应与事件签名，公钥与指纹在文档页与门户**双渠道公示**（可本地实算指纹自检）。你可以自行轮换自己的签名密钥；平台侧换钥会同时发布新 `kid` 与新公钥，新旧并存期内按 `kid` 选择公钥。**紧急吊销不受宽限影响**，宽限窗最长 72 小时。详见 [凭证与密钥管理](./docs/12-credential-key-management.md)。

## 本资料的书写纪律

- **金额**一律整数分（字段后缀 `Fen`），仅人民币。
- **字段名**：机器可读面一律使用平台字段名（形如 `qrCode`）；来源系统的原始字段名不在本资料出现。
- **发卡与交付**：平台只负责收款与支付事实；**卡密/发货等交付动作由商家自建系统承担**——收银页不承载交付内容。
- **终态可信边界**：收银页打开、收银页回跳、用户点击完成**都不等于**支付终态；终态只认服务端订单状态（查单接口）或经验签的事件通知。
- **费率、限额、到账时效、通道放行**都属于会变更的口径：本资料**一律不写死**，只指向生效配置与每单投影。
